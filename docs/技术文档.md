### 1.1 文档目的

本文档描述「错因本」Android APK 的技术实现方案，包括架构设计、模块划分、数据层设计、关键技术选型与集成方式、工程结构、开发规范及部署流程。

### 2.2 选型理由

**为什么用 Jetpack Compose**：Compose 是 Google 推荐的现代 Android UI 工具包，与 Kotlin 语言深度集成，代码量少、可测试性强。使用 `NavHost` + `NavigationBar` 实现底部导航和页面切换，通过 `NavController.currentBackStackEntryAsState()` 将导航状态提升到 `BottomNavigation` 组件，实现状态自动同步。

**为什么用 Room**：Room 是 Android Jetpack 的持久化库，在编译期校验 SQL，支持 Kotlin Coroutines 和 Flow 一等公民集成。Room 直接支持 Kotlin Flow 编写可观察查询，每当数据库数据变更时自动发出新值。对于错因频次统计这类需要响应式更新的场景（录题后首页排行自动刷新），Flow + Room 的组合是最优解。

**为什么用 Hilt**：Google 推荐的 Android 依赖注入方案。对于本项目的 Repository、DAO、OCR 服务等组件，使用 Hilt 进行构造函数注入，减少手动依赖管理。

**为什么用 ML Kit**：Google ML Kit 文字识别 API 支持从图像和视频中提取文本，运行在 API 21 及以上设备，端侧运行、离线可用、无需网络权限。对中文题目识别效果良好。

### 3.3 数据流

采用单向数据流（UDF）：

```
用户操作 → ViewModel 接收事件 → 调用 UseCase
    → Repository 读写 Room → Flow 发出新数据
    → ViewModel 更新 UiState → Compose 重组 UI
```

ViewModel 使用 `StateFlow` 暴露 UI 状态，Compose 通过 `collectAsStateWithLifecycle()` 订阅。Room DAO 返回 `Flow<T>`，数据变更自动推送，无需手动刷新。

### 4.2 核心 DAO 查询

```kotlin
@Dao
interface ReasonDao {

    // 错因排行榜：按出错次数降序，返回 Flow 实现自动刷新
    @Query("""
        SELECT r.id, r.name, r.category, r.color,
               COUNT(DISTINCT qr.questionId) AS wrongCount,
               MAX(qr.createdAt) AS lastWrongAt
        FROM reasons r
        JOIN question_reasons qr ON r.id = qr.reasonId
        JOIN questions q ON q.id = qr.questionId
        WHERE r.isArchived = 0
          AND (:subjectId IS NULL OR q.subjectId = :subjectId)
        GROUP BY r.id
        ORDER BY wrongCount DESC, lastWrongAt DESC
    """)
    fun getReasonRanking(subjectId: Long?): Flow<List<ReasonWithCount>>

    // 时间范围内的错因排行
    @Query("""
        SELECT r.id, r.name, r.category, r.color,
               COUNT(DISTINCT qr.questionId) AS wrongCount,
               MAX(qr.createdAt) AS lastWrongAt
        FROM reasons r
        JOIN question_reasons qr ON r.id = qr.reasonId
        WHERE r.isArchived = 0
          AND qr.createdAt >= :since
        GROUP BY r.id
        ORDER BY wrongCount DESC
    """)
    fun getReasonRankingSince(since: Long): Flow<List<ReasonWithCount>>

    // 相似错因搜索（防重复）
    @Query("SELECT * FROM reasons WHERE name LIKE '%' || :keyword || '%' AND isArchived = 0")
    suspend fun searchSimilar(keyword: String): List<ReasonEntity>
}

// 查询结果 POJO
data class ReasonWithCount(
    val id: Long,
    val name: String,
    val category: String?,
    val color: String?,
    val wrongCount: Int,
    val lastWrongAt: Long
)
```

**注意事项**：`COUNT(DISTINCT qr.questionId)` 使用 DISTINCT 避免同一题关联多个相同错因时重复计数。在 Room 中使用 `JOIN` + `GROUP BY` 实现多表关联统计查询，Room 支持多重映射返回值类型。

### 5.2 OcrService 封装

```kotlin
class OcrService @Inject constructor(
    @ApplicationContext private val context: Context
) {
    private val recognizer = TextRecognition.getClient(
        TextRecognizerOptions.DEFAULT_OPTIONS
    )

    suspend fun recognize(imageUri: Uri): Result<String> = suspendCancellableCoroutine { cont ->
        val image = InputImage.fromFilePath(context, imageUri)
        recognizer.process(image)
            .addOnSuccessListener { visionText ->
                // 后处理：去除多余空白、按行整理
                val cleaned = visionText.text
                    .lines()
                    .map { it.trim() }
                    .filter { it.isNotEmpty() }
                    .joinToString("\n")
                cont.resume(Result.success(cleaned))
            }
            .addOnFailureListener { e ->
                cont.resume(Result.failure(e))
            }
    }
}
```

### 5.3 OCR 结果处理策略

- 识别文本自动去除多余空白和空行。
- 公式、图形不做强行文本转换，保留原图。
- 识别结果在 UI 层可编辑，用户可手动修正。
- OCR 失败时降级为手动输入模式。

**注意**：ML Kit 的文字识别 API 支持 API 21 及以上设备，端侧运行。对中文题目识别效果良好，但对复杂数学公式识别有限，MVP 阶段公式保留原图即可。

### 6.3 图片压缩策略

采用“先缩放再压缩”的双降负机制：

```kotlin
object ImageCompressor {
    suspend fun compress(inputFile: File, outputFile: File, maxSizeKB: Int = 500) {
        // 1. 采样缩放
        val options = BitmapFactory.Options().apply { inJustDecodeBounds = true }
        BitmapFactory.decodeFile(inputFile.absolutePath, options)

        var sampleSize = 1
        while (options.outWidth / sampleSize > 2048) {
            sampleSize *= 2
        }

        val decodeOptions = BitmapFactory.Options().apply {
            inSampleSize = sampleSize
        }
        val bitmap = BitmapFactory.decodeFile(inputFile.absolutePath, decodeOptions)

        // 2. JPEG 质量压缩
        var quality = 90
        var outputStream: FileOutputStream
        do {
            outputStream = FileOutputStream(outputFile)
            bitmap.compress(Bitmap.CompressFormat.JPEG, quality, outputStream)
            outputStream.close()
            quality -= 10
        } while (outputFile.length() / 1024 > maxSizeKB && quality > 30)

        bitmap.recycle()
    }
}
```

**图片存储位置**：应用沙箱 `filesDir/images/` 目录，文件名使用 `UUID.randomUUID().toString() + ".jpg"`。

### 7.2 导出到用户指定目录

使用 Storage Access Framework（SAF）实现用户选择导出目录。系统授予应用对用户所选 URI 的读写访问权限，无需额外声明存储权限。SAF 权限通过系统文件夹选择器授予，不需要在 `AndroidManifest.xml` 中声明额外权限。

```kotlin
class FileSaveManager @Inject constructor(
    @ApplicationContext private val context: Context
) {
    // 启动目录选择器
    fun createDirectoryPickerIntent(): Intent {
        return Intent(Intent.ACTION_OPEN_DOCUMENT_TREE).apply {
            addFlags(Intent.FLAG_GRANT_READ_URI_PERMISSION)
            addFlags(Intent.FLAG_GRANT_WRITE_URI_PERMISSION)
            addFlags(Intent.FLAG_GRANT_PERSISTABLE_URI_PERMISSION)
        }
    }

    // 持久化 URI 权限
    fun persistPermission(uri: Uri) {
        context.contentResolver.takePersistableUriPermission(
            uri,
            Intent.FLAG_GRANT_READ_URI_PERMISSION or
            Intent.FLAG_GRANT_WRITE_URI_PERMISSION
        )
    }

    // 在用户选定目录中创建文件
    suspend fun writeToDirectory(
        treeUri: Uri,
        fileName: String,
        mimeType: String,
        content: ByteArray
    ): Result<Uri> = withContext(Dispatchers.IO) {
        try {
            val directory = DocumentFile.fromTreeUri(context, treeUri)
            val file = directory?.createFile(mimeType, fileName)
                ?: return@withContext Result.failure(IOException("无法创建文件"))

            context.contentResolver.openOutputStream(file.uri)?.use { output ->
                output.write(content)
            }
            Result.success(file.uri)
        } catch (e: Exception) {
            Result.failure(e)
        }
    }
}
```

### 7.3 PDF 导出

使用 Android 原生 `PdfDocument` 生成错因清单 PDF：

```kotlin
class PdfExporter @Inject constructor(
    @ApplicationContext private val context: Context
) {
    fun exportReasonList(
        reasons: List<ReasonWithCount>,
        questionsByReason: Map<Long, List<QuestionEntity>>,
        outputStream: OutputStream
    ) {
        val pdfDocument = PdfDocument()
        val pageInfo = PdfDocument.PageInfo.Builder(595, 842, 1).create() // A4
        var page = pdfDocument.startPage(pageInfo)
        var canvas = page.canvas
        var y = 50f

        reasons.forEach { reason ->
            // 绘制错因标题
            val paint = Paint().apply {
                textSize = 16f
                isFakeBoldText = true
            }
            canvas.drawText("${reason.name}（${reason.wrongCount}次）", 40f, y, paint)
            y += 30f

            // 绘制代表题缩略图
            questionsByReason[reason.id]?.take(5)?.forEach { question ->
                val bitmap = BitmapFactory.decodeFile(question.imagePath)
                bitmap?.let {
                    val scaled = Bitmap.createScaledBitmap(it, 200, 150, true)
                    canvas.drawBitmap(scaled, 40f, y, null)
                    y += 160f
                }
            }

            if (y > 750) {
                pdfDocument.finishPage(page)
                page = pdfDocument.startPage(pageInfo)
                canvas = page.canvas
                y = 50f
            }
        }

        pdfDocument.finishPage(page)
        pdfDocument.writeTo(outputStream)
        pdfDocument.close()
    }
}
```

**导出流程**：

```
选择导出格式 → 生成内容到临时文件
→ 启动 SAF 目录选择器 → 用户选择目录
→ persistPermission(treeUri)
→ 写入文件到用户选定目录 → 提示成功
```

### 8.2 ViewModel 与 UiState

```kotlin
data class HomeUiState(
    val isLoading: Boolean = true,
    val reasons: List<ReasonWithCount> = emptyList(),
    val selectedSubjectId: Long? = null,
    val timeRange: TimeRange = TimeRange.ALL
)

@HiltViewModel
class HomeViewModel @Inject constructor(
    private val reasonRepository: ReasonRepository
) : ViewModel() {

    private val _selectedSubject = MutableStateFlow<Long?>(null)
    private val _timeRange = MutableStateFlow(TimeRange.ALL)

    val uiState: StateFlow<HomeUiState> = combine(
        _selectedSubject,
        _timeRange
    ) { subjectId, range ->
        subjectId to range
    }.flatMapLatest { (subjectId, range) ->
        when (range) {
            TimeRange.ALL -> reasonRepository.getReasonRanking(subjectId)
            TimeRange.LAST_7_DAYS -> reasonRepository.getReasonRankingSince(
                System.currentTimeMillis() - 7 * 24 * 3600_000L
            )
            TimeRange.LAST_30_DAYS -> reasonRepository.getReasonRankingSince(
                System.currentTimeMillis() - 30 * 24 * 3600_000L
            )
        }
    }.map { reasons ->
        HomeUiState(isLoading = false, reasons = reasons)
    }.stateIn(
        scope = viewModelScope,
        started = SharingStarted.WhileSubscribed(5000),
        initialValue = HomeUiState()
    )

    fun selectSubject(subjectId: Long?) { _selectedSubject.value = subjectId }
    fun selectTimeRange(range: TimeRange) { _timeRange.value = range }
}
```

### 8.3 复习模式交互

错因详情页（复习模式）核心交互：

```
默认状态：显示题目缩略图/OCR文本，不显示答案
    ↓
用户思考"我为什么错"
    ↓
点击"显示错因" → 展开错因标签和备注
    ↓
用户点击反馈按钮：
    [记住了] → reviewLogs 写入 remembered，错因计数不增加
    [又错]   → reviewLogs 写入 wrong，错因计数 +1
    [模糊]   → reviewLogs 写入 fuzzy，错因计数不增加
    ↓
自动进入下一题 / 返回列表
```

## 10. 开发规范

### 10.1 代码规范

| 规范 | 要求 |
|---|---|
| 语言 | 100% Kotlin，禁止 Java |
| 格式 | ktlint + spotless |
| 命名 | 遵循 Kotlin 官方命名规范 |
| 异步 | 统一使用 Coroutines + Flow，禁止 AsyncTask |
| 线程 | 数据库操作在 IO 线程，UI 操作在主线程 |
| 状态 | ViewModel 使用 StateFlow 暴露 UI 状态 |
| 错误处理 | 统一 Result 封装，UI 层显示友好提示 |

### 10.2 Compose 规范

- 每个页面分为 Screen（连接 ViewModel）和 Content（纯 UI）两个 Composable。
- Content 函数不持有 ViewModel，接收 UiState 和回调，便于 Preview。
- 列表使用 `LazyColumn` + `key` 参数优化性能。
- 图片加载使用 Coil 的 `AsyncImage`。

### 10.3 数据库规范

- 所有 Entity 加 `@Entity` 注解和必要索引。
- DAO 查询返回 `Flow<T>` 实现响应式更新。
- 写操作使用 `suspend` 函数。
- 数据库迁移使用 `Migration` 对象，禁止 `fallbackToDestructiveMigration`。

## 12. 性能优化

### 12.1 启动优化

- `Application.onCreate()` 中不执行耗时操作。
- Hilt 依赖注入按需初始化，避免启动时创建所有单例。
- 数据库使用懒加载，首次访问时才创建。

### 12.2 列表性能

- `LazyColumn` 使用 `key` 参数标识每项。
- 图片使用 Coil 加载并缓存，设置合适的 `size` 参数。
- 错因排行榜列表项使用 `derivedStateOf` 避免不必要重组。

### 12.3 内存优化

- 图片压缩后再存储，避免加载大图导致 OOM。
- Bitmap 使用后及时 `recycle()`。
- 大图片使用 `BitmapFactory.Options.inSampleSize` 采样加载。

### 12.4 数据库优化

- 对频繁查询的字段建索引。
- 统计查询使用 `COUNT(DISTINCT ...)` 避免重复计数。
- 批量写入使用 `@Transaction` 包裹。

## 14. 风险与应对

| 风险 | 影响 | 应对 |
